# Cloudflare R2 — o que hospedar para o ultravideo

R2 é **object storage**: serve arquivos estáticos. Para API (metadados, catálogo verificado, sync) você coloca um **Worker** na frente, na mesma zona.

> A API `u-api.palv.org` roda no **mesmo Worker** (`worker/api.mjs`) e faz proxy
> para a VPS. Escopo completo em `docs/API.md`; schema SQL em `sql/schema.sql`.

## Setup (já deixado pronto no repo)

1. Crie o bucket `ultra-content` no R2.
2. Anexe o domínio `u-content.palv.org` ao bucket (Custom Domains).
3. Em `wrangler.toml`, preencha `zone_id` (e opcionalmente `account_id`).
4. Rode `npx wrangler login` e depois:
   ```bash
   npx wrangler deploy                  # sobe worker/index.mjs
   ```
   O backend de metadados fica na sua **VPS**. O Worker apenas faz proxy para
   `METADATA_ORIGIN` (configure em `wrangler.toml`) e guarda a resposta no
   **Cache API da Cloudflare** por 24h — o cache é hospedado pela CF, na borda,
   e pode ser expirado a qualquer momento. Nenhum `TMDB_KEY` é necessário no Worker.
5. Suba os arquivos estáticos (comandos abaixo).

O Worker (`worker/index.mjs`) já aplica CORS, Cache-Control por caminho e o proxy de metadados com cache de 24h. **Você não precisa configurar Cache Rules manualmente.**

Domínio do ecossistema: **`u-content.palv.org`** (tudo ultra — ultravideo, anime, music — usa este host).

- **Ad frame (AdSense/GAM): use `u-content.palv.org`** — `*.r2.dev` costuma ser recusado por AdSense/IMA e por regras de iframe.
- **APK, assets, envelope e catálogo:** podem usar `u-content.palv.org` ou `*.r2.dev` (nesse caso o CSP do app também precisa liberar o host).

| Caminho no R2 | Origem no repo | Para que serve |
|---|---|---|
| `/ads/frame.html` | `design/ads-frame.html` | Frame de anúncio do desktop (AdSense/GAM) — precisa HTTPS |
| `/ui/envelope.json` | `scripts/sign-ui.mjs` + `design/remote-ui.sample.json` | Descritor de UI assinado (ECDSA P-256) |
| `/addons/catalog.json` | a gerar depois | Catálogo verificado de add-ons (JSON, sem conteúdo) |
| `/apk/ultravideo-v0.1.0.apk` | build Tauri Android | Download direto do APK |
| `/updates/latest.json` | a gerar na v1.0 | Manifest do updater |
| `/assets/poster-fallback.webp` | a criar | Placeholder de pôster quando o add-on não manda imagem |
| `/assets/logo-mark.png` | `src/assets/uvideo-mark-sm.png` | Logo para site/Share/discord |

## Headers recomendados (Cache Rules ou Worker)

| Path | Cache-Control | Content-Type | Observação |
|---|---|---|---|
| `/ads/frame.html` | `public, max-age=3600` | `text/html` | **Não** enviar `X-Frame-Options: DENY/SAMEORIGIN` |
| `/ui/envelope.json` | `public, max-age=300` | `application/json` | CORS `*` |
| `/addons/catalog.json` | `public, max-age=600` | `application/json` | CORS `*` |
| `/apk/*` | `no-cache` | `application/vnd.android.package-archive` | `Content-Disposition: attachment` |
| `/assets/*` | `public, max-age=31536000, immutable` | conforme extensão | Hash no nome do arquivo |
| `/legal/*` | `public, max-age=86400` | `text/html` | — |
| `/updates/latest.json` | `no-cache` | `application/json` | CORS `*` |

CORS para os JSON públicos:
```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, OPTIONS
```
(origem do WebView é `tauri://localhost` no desktop e `http://tauri.localhost` no Android).

## Comandos (Wrangler)

```bash
wrangler r2 object put uv-cdn/ads/frame.html --file design/ads-frame.html --content-type text/html
wrangler r2 object put uv-cdn/ui/envelope.json --file envelope.json --content-type application/json
wrangler r2 object put uv-cdn/assets/logo-mark.png --file src/assets/uvideo-mark-sm.png --content-type image/png
wrangler r2 object put uv-cdn/apk/ultravideo-v0.1.0.apk --file ultravideo.apk --content-type application/vnd.android.package-archive
```

Depois, em **Cloudflare Dashboard → R2 → bucket → Settings → Custom Domains**, anexe `u-content.palv.org`.

## Worker na frente (quando precisar de API)

Rotas sugeridas:
- `GET /api/metadata/search?q=` → TMDB/TVMaze/AniList com cache no R2 (evita expor chave no app).
- `GET /api/catalog/verified` → catálogo assinado.
- `POST /api/sync/push` / `GET /api/sync/pull` → sync pago (usuário autenticado via Discord).
- `GET /api/updates/latest` → manifest versionado.

Use `caches.default` do Worker + KV/R2 para o cache. Isso é o que deixa o app **rápido**: o celular faz 1 request agregado em vez de N.

## Cache de vídeo: use Workers Caching, não Cache API

`caches.default` serve para JSON/metadados pequenos. Para MP4/MKV com muitos usuários simultâneos:

- **Limite:** 512 MB por objeto (não cacheia arquivos maiores).
- **Escopo:** por data center — não replica entre PoPs.
- **Concorrência:** não agrupa requests — N usuários no mesmo arquivo novo = N buscas na VPS.

Para vídeo, configure uma **Cache Rule "Cache Everything"** em `u-content.palv.org/video/*` e use `fetch()` no Worker (Workers Caching tem tiered caching, coalescing e Range). Headers:
```
Cache-Control: public, max-age=86400
Accept-Ranges: bytes
```
Só para fonte legal (archive.org, domínio público, seus arquivos). Torrent continua no dispositivo.

**Nunca** coloque `caches.default`/Cache Rule em endpoints de usuário (`/api/user/*`, sync, SQL): use `Cache-Control: private, no-store`.

## Proxy de imagem (estilo wsrv.nl)

`GET /api/image?url=https://image.tmdb.org/...` — allowlist de hosts em `worker/index.mjs`, cache de 24h na borda. Use `u-api.palv.org` como origin de metadados (`METADATA_ORIGIN` no `wrangler.toml`).

## TTL recomendado

| Dado | TTL |
|---|---|
| Metadados (TMDB/TVMaze/AniList) | 24h — na sua **VPS**, não no R2 |
| Catálogo verificado de add-ons | 10 min |
| Envelope de UI assinado | 5 min |
| EPG / programação de live | 1–6h |
| Índice de legendas | 24h |
| Arquivos de legenda | 1h |
| Pôsteres/thumbnails | 30 dias, `immutable` |
| Ad frame | 1h |
| APK | `no-cache` (nome versionado) |
| Conteúdo de vídeo (MKV/MOV/MP4) | **Nunca no servidor** — fica no dispositivo via `librqbit` |

## O que NÃO colocar no R2

- Conteúdo de vídeo/torrent (risco legal e custo de egress).
- Código executável do app (o app não baixa JS remoto).
- Dados pessoais dos usuários (library, histórico) sem criptografia e consentimento.
